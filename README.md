# OSCE SMM · Donbas, January–February 2022

Интерактивный исторический атлас наблюдений Специальной мониторинговой миссии ОБСЕ (СММ) за **1 января — 20 февраля 2022 года**. При локальном запуске без предварительной загрузки официальных отчётов используется исходный резервный набор за **14–20 февраля**.

Публичная версия: [r9s4x0m.github.io/osce_2022_atlas](https://r9s4x0m.github.io/osce_2022_atlas/).

Альтернативная опубликованная версия: [osce-feb22-atlas.resourcefulbat.chatgpt.site](https://osce-feb22-atlas.resourcefulbat.chatgpt.site/).

## Что показывает атлас

- Обозначенные кругами приблизительные позиции камер и наблюдателей СММ; это **не** GPS-координаты патрулей.
- Оценочные районы наблюдавшихся нарушений — ромбы с суммой опубликованного ОБСЕ количества («К-во») и полупрозрачные зоны неопределённости.
- Пять категорий предполагаемой территории события: подконтрольная уверенно / вероятно, неизвестно, неподконтрольная вероятно / уверенно.
- Фильтры по времени, типу нарушения, способу наблюдения, территории и текстовому поиску. **Всё состояние фильтров и включённых слоёв хранится в URL после `#`**, поэтому ссылками можно делиться.
- Журнал первичных строк и экспорт CSV. Записи в журнале, на карточках групп и в карточках наблюдателей сортируются по **возрастанию времени события**.

Важные ограничения:

1. Географические координаты и категории территории **приблизительные**. Исходные данные не устанавливают, кто произвёл выстрел.
2. Для наблюдения *в населённом пункте* цвет позиции берётся из текста ОБСЕ либо отдельного опубликованного подтверждения. Для патруля *от населённого пункта* принимается **та же сторона, что у ориентира из отчёта**, с явной отметкой об этом допущении. Это не независимо подтверждённая GPS-позиция. Если сторона не указана ОБСЕ, категория остаётся неизвестной. Колонка `Контроль` исходной пользовательской таблицы **не используется** для классификации.
3. Ромбы группируют строки на экране для удобства. Это не дедупликация событий. Суммы берутся из опубликованного количества в исходных строках.
4. Исходный слой линии соприкосновения — приближённый контур апреля 2021 года, не точная геометрия на каждый день февраля 2022-го.
5. «Уверенно» означает, что **весь круг модельной неопределённости события** лежит по одну сторону исходного контура. В его радиус входит неопределённость координат позиции наблюдателя. Это не подтверждение точности самого исторического контура.
6. Для положения патруля, заданного смещением от ориентира, используем условный диаметр **10% указанной дальности** (100 м при 1 км; модельный радиус — 5%). Это **не калиброванный доверительный интервал ОБСЕ**. Неопределённость картографического центра ориентира в малый круг не входит, но **добавляется при расчёте круга неопределённости события и его территории**. Грубость компасного обозначения направления патруля остаётся отдельным неучтённым фактором.

## Источники и воспроизводимость

- [Исходная таблица исследователя](https://docs.google.com/spreadsheets/d/12UFpinZWtTaa69D3JMANVHEa7lkPqVYaUIII-nCtZGs/edit).
- [Официальные ежедневные отчёты ОБСЕ](https://www.osce.org/ukraine-smm/reports) и приложения с перечнями нарушений режима прекращения огня.
- `source/osce_sheet_rows.json`: исходная выгрузка строк для 14–20 февраля.
- `source/previous_approximate_locations.geojson`: вспомогательные географические ориентиры с собственными ссылками на источники.
- `source/observer_reference_points_2022.json`: проверенные картографические опорные точки населённых пунктов и вокзалов (отдельно от текста ОБСЕ), с URL геоданных.
- `source/osce_2022_referenced_settlements.json`: дополнительный сверенный справочник населённых пунктов с координатами и идентификаторами OpenStreetMap; сопоставление одноимённых пунктов с географическим описанием ОБСЕ. Данные населённых пунктов: [bnotezz/ua-settlements](https://github.com/bnotezz/ua-settlements) и [участники OpenStreetMap](https://www.openstreetmap.org/copyright) (ODbL).
- `scripts/import_osce_2022.py`: загрузчик официальных русскоязычных PDF-приложений к **40 отчётам № 1–40/2022**. Извлекает наблюдения именно по дате события, сохраняет первичные PDF URL, номер страницы и SHA-256. При отсутствии отчёта, неразобранной строке или ошибке загрузки завершает сборку ошибкой.
- `source/osce_2022_official_rows.json`: извлечённые строки за 01.01–20.02, генерируются workflow; исходные PDF остаются у ОБСЕ.
- `source/osce_reports_2022_index.json`: машинопроверяемый список PDF и результаты контроля полноты, генерируется workflow.
- `build_data.py`: применяет к ориентиру расстояние и азимут из описания наблюдателя (не использует километраж в скобках от Донецка/Луганска), строит `dist/data/events.json`, `dist/data/geography.json`, `dist/data/observer_locations.csv` и **`dist/data/unmapped_patrols.csv`** (полный список патрульных описаний без координат и причин пропуска). При наличии валидированного официального импорта предпочитает его исходной таблице исследователя.
- Отдельно геопривязаны районы Золотое-2/3/4/5. Для Золотого-4 точка привязана **к шахте «Родина»**, а не к измеренному центру квартала. Контроль стороны наблюдателя по-прежнему берётся из официального текста ОБСЕ. Специальные КПВВ и блокпосты без проверенной географической точки не заменяются центром ближайшего населённого пункта.
- `scripts/analyze_osce_2022.py`: строит `dist/data/analysis.json`, `dist/data/daily.csv` и `dist/data/provenance.json` с итогами по дням, территориям, видам инцидентов и методам наблюдения.
- `tests/test_pipeline.py`: офлайн-тесты извлечения и агрегации без обращения к сайту ОБСЕ.

**Важно:** показатель «К-во» — количественное поле официальной строки. Сумма может не совпадать с числом независимо идентифицированных физических происшествий. Мы не объединяем похожие записи разных источников автоматически и не приписываем инциденты стороне, открывшей огонь. Территориальная классификация событий остаётся приблизительной.

## Воспроизвести сборку

```sh
python3 -m pip install -r requirements-analysis.txt
python3 -m unittest discover -s tests -v
python3 scripts/import_osce_2022.py --cache-dir /tmp/osce-2022-cache
python3 build_data.py
python3 scripts/analyze_osce_2022.py
python3 -m http.server 8000 --directory dist
```

Загрузка получает открытые отчёты с `www.osce.org` и выполняется на GitHub runner. При недоступности сайта или изменении формата таблиц сборка **останавливается и не обновляет Pages**; диагностический индекс доступен среди артефактов GitHub Actions.

## Локальный запуск

Сайт не требует серверного приложения и не отправляет данные наблюдений картографическому провайдеру.

```sh
python3 -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000/`.

## GitHub Pages

В настройках репозитория выберите **Settings → Pages → Build and deployment → Source: GitHub Actions**. На push или по `Run workflow` запустится `.github/workflows/pages.yml`:

1. `build` — тестирует парсер, собирает 40 оригинальных приложений, проверяет полноту, строит географические данные и таблицы статистики, сохраняет артефакт `osce-2022-audit`;
2. `deploy` — **только после успешного `build`** публикует `dist/` через GitHub Pages.

Папка `dist/` содержит рабочий резервный набор за февраль для предпросмотра исходного репозитория. При штатном запуске GitHub Actions он заменяется полной реконструкцией за январь–февраль.
